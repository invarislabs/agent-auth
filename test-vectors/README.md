# Test vectors

Language-independent test cases for AgentAuth verifiers. Every implementation (the Python package in this repo, the TypeScript verifier in [`ts/`](../ts/), and any other) must produce exactly the outcomes recorded here. If two implementations pass every vector, they accept and reject the same inputs.

The files are generated by [`scripts/generate_test_vectors.py`](../scripts/generate_test_vectors.py) from the Python reference implementation, with fixed keys, timestamps and grant ids, so every run produces identical bytes. Before writing each case, the generator checks that Python actually gives the intended outcome. CI fails if the committed files are stale (`python scripts/generate_test_vectors.py --check`). **Don't edit them by hand**: change the generator and regenerate.

All binary values are standard base64 (`*_b64` fields). "Now" for every time-dependent case is in the case (`now`, unix seconds) or is `1800000000` (2027-01-15T08:00:00Z).

| File | Contents |
|---|---|
| `primitives.json` | base58btc, multikeys, digests, key commitments, canonical JSON (including key ordering by code point and string escaping), and signature checks with non-canonical encodings |
| `kel.json` | Key event logs. Valid ones carry the expected derived state; invalid ones must be rejected. Controller signatures are checked against the embedded key only, except in cases with `valid_with_controller_binding`: those must also be verified with controller keys bound to the log named in `controller_log` (any key in its history), and give that outcome. |
| `requests.json` | `AgentSig` verification. `keys` maps each DID to its current `{key, kid}`; `audiences` and `max_skew` configure the verifier. Each case gives the `Authorization` header, the method, raw path, body and `AgentGrant` value the verifier sees, and `repeat` (send it that many times, sharing one replay cache). `expect` has one entry per attempt: `{"valid": true, "did", "kid"}` or `{"valid": false, "status"}` (401 = authentication failure). |
| `grants.json` | `AgentGrant` chain verification against `keys`, `root_policy` (`{principal: [scopes]}`), the case's `revoked` list of `[issuer, grant id]`, `requester`, `audience` and `now`. Valid cases give the principal, delegation path (`via`), effective scopes, grant ids and the leaf's limits. Invalid ones give the HTTP status (400 malformed, 401 no grant, 403 refused). Also scope and audience covering rules. |
| `limits.json` | Limit parsing (`invalid` must all be rejected), narrowing (`violation`: would the child loosen the parent?), per-call checks (`check_call`, with status 400/403 on rejection), and resource pattern matching and covering. Stateful counters (budgets, rates, uses) aren't covered: they depend on the service's ledger. |
| `revocations.json` | Revocation events checked against an issuer key. For registry clients, `issuer_log` is the issuer's key event log, and `forged_proof` is a well-formed revocation of the valid case's grant signed by a key the issuer never held (a proof that must not count). |

Rejections are recorded by HTTP status, not by message, so implementations are free to word their errors differently.
